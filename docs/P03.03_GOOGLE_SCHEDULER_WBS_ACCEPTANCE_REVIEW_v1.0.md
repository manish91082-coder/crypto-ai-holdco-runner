## 5. Security and replay assessment
The candidate's OIDC verifier checks the Google signature using JWKS and binds exact issuer, audience and SHA-256(subject). Missing configuration fails closed. The Apps Script manifest uses only openid and script.external_request; no email/profile or Drive scope is requested.

The replay SQL proposes a unique tick UUID and unique SHA-256 token hash. This is at-most-once admission, not exactly-once processing. A key operational assumption remains untested: Google Apps Script must provide a fresh token digest for each legitimate scheduler invocation. If a still-valid token is reused for a later 30-minute tick, the unique token-hash constraint will reject it as HTTP 409. Require a separate-execution freshness test before scheduling.
