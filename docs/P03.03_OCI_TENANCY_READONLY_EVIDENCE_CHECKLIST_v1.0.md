## 2. Read-only Console procedure

Sign in only if an OCI account already exists. Use the official Console URL: https://cloud.oracle.com

### Evidence A — Home Region

1. Open the profile menu in the upper-right navigation bar.
2. Select `Tenancy: <tenancy-name>`.
3. On Tenancy Details, capture only the **Home Region** value.

Oracle's documentation states that the Home Region is selected when the tenancy is provisioned and cannot be changed afterward. Always Free Compute must be provisioned in that Home Region.

### Evidence B — Compute limit and usage

1. Open the navigation menu.
2. Select **Governance & Administration**.
3. Under **Tenancy Management**, select **Limits, Quotas and Usage**.
4. Set Service to **Compute** and, where available, set Region to the Home Region and Scope/Compartment to the tenancy/root scope.
5. Capture the rows for the A1/Arm Compute OCPU and memory limits, showing **Service Limit**, **Usage**, and **Available**.

Oracle's published Always Free allowance is the first 1,500 OCPU-hours and 9,000 GB-hours per month for VM.Standard.A1.Flex, equivalent to 2 OCPUs and 12 GB memory for an Always Free tenancy. This published allowance does not establish the specific tenancy's remaining capacity or host availability.

### Evidence C — Key Management / Vault limits

1. On the same **Limits, Quotas and Usage** page, select Service **Key Management**.
2. Capture the HSM-protected master-key-version limit and usage/available values, where shown.
3. If the Console distinguishes Virtual Vaults, Private Vaults, software-protected keys or HSM-protected keys, preserve that distinction in the screenshot.

Oracle publishes 20 HSM-protected master-key versions and 150 Always Free Vault secrets per tenancy; Private Vaults are excluded. The first 20 HSM key versions are included in the free allowance; any use outside the included allocation must be treated as potentially billable. Do not create a vault, key or secret to test this.

### Evidence D — Current network inventory (only if a VCN already exists)

1. Open **Networking → Virtual Cloud Networks**.
2. Inspect the existing VCN list only. Do not create a VCN or gateway.
3. If a VCN already exists, open it and inspect its existing Gateways tab and subnet/route-table summaries.
4. Record whether an Internet Gateway, NAT Gateway or Service Gateway already exists. Do not reveal public IP addresses or OCIDs.

A Service Gateway is free but gives access only to supported Oracle Services Network endpoints; it does not provide a route to the external Neon API. Neon requires an appropriate public internet egress path. A NAT Gateway allows outbound-only internet access for private instances. The complete account-specific cost behavior of the proposed NAT/public-egress configuration is not yet verified; do not provision it.

### Evidence E — Subscription / billing posture

If already visible in the account, capture the account's current subscription type and whether the account is Free-Trial, Always-Free-only or Pay-As-You-Go. Redact personal, payment and tenancy identifiers. Do not add a payment method, upgrade, enable billing, request a limit increase or change spending settings.

| Existing egress components | Internet Gateway / NAT Gateway / Service Gateway / none / unsure |

A missing row on the Limits page is not proof that a service is unavailable. Oracle states that the Console might not display limits/usage for every service or resource; mark such fields UNKNOWN rather than inferring zero.

## 4. Redaction rules

Before sharing, cover or crop:

- Tenancy name, Tenancy OCID, Compartment OCIDs and resource OCIDs.
- Username, email address, phone number and identity-domain details.
- Public IP addresses, private CIDRs, hostnames, route details containing private infrastructure identifiers.
- Payment card, billing address, invoice identifiers and other financial account details.
- API keys, auth tokens, client secrets, private keys, certificates and recovery material.

Do not send secrets in chat under any circumstance. The project needs only the Home Region label, subscription category and aggregate limit/usage values.

## 5. Decision rules after evidence arrives

| Gate | Pass condition | Failure disposition |
|---|---|---|
| Existing tenancy | Existing authenticated tenancy confirmed | Do not create one under the current zero-upfront scope |
| Home Region | Identified and Compute/Vault services available there | Reject this OCI placement if required services cannot be supported |
| Account/payment posture | Free resources are usable without upgrading, billing linkage or automatic paid fallback | Reject if paid account/overage exposure is unavoidable |
| A1 capacity | Remaining Always Free allowance and shape eligibility evidenced in Home Region | Reject if no free capacity or only paid capacity is available |
| HSM capacity | At least one included HSM key version remains available in eligible Vault type | Reject if only paid/Private Vault path remains |
| Network egress | Neon can be reached without an unverified or chargeable network service; no silent overage | Block until exact no-bill route is proven |
| Security | Exact-instance IAM and SSH privilege inheritance can be constrained | Reject if signing authority cannot be isolated |

A GO at this stage only allows proposing a separately authorised, bounded sandbox test. It does not authorise resource creation, live signing, Neon branch creation, Data API enablement, Function deployment, triggers, recurring workloads or production execution.
