## 5. One-response / one-phase execution contract

Every assistant work response must stay inside **one active WBS phase**. Do not work on multiple phases in parallel or introduce unrelated projects, codebases, tools or deliverables.

For each response:

1. Recover canonical project identity and latest checkpoint before acting.
2. Name the one active phase and the exact numbered task being advanced.
3. State that response's bounded objective and allowed execution scope.
4. Perform the work; prefer deterministic tests and primary-source checks.
5. Verify the result independently: tests, read-back, hashes, permissions, cost/quota and negative tests as applicable.
6. Update the phase evidence and continuity only after verification.
7. Mark a task/phase COMPLETE only when its exact acceptance gate passes. Otherwise mark PARTIAL, BLOCKED or NOT STARTED, record the missing evidence, and stay in the same phase.
8. End with the same compact control card: ultimate goal; first implementation goal; active phase/task; work completed this response; test/evidence result; blockers; next single action.

**Important:** “one phase per response” means one phase is the only execution scope. It does not permit declaring a whole phase complete in one message when its five tasks or exit gate have not passed. A blocked phase is never skipped to make the dashboard look green.
