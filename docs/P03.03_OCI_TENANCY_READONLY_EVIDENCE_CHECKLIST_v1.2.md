## 1. Existing account and subscription type — new mandatory gate

If an OCI account already exists, sign in at https://cloud.oracle.com. Do not sign up or upgrade.

Record only the visible account/subscription classification:
- Always-Free-only / Free Tier, not upgraded;
- standard Free Trial, not upgraded;
- special Free Trial offer whose post-trial Always Free continuation may differ;
- Pay-As-You-Go or other paid subscription.

Also record whether an account upgrade was ever completed. Do not click Upgrade, Convert, Activate paid account, or similar actions.

**Gate interpretation:** Oracle documents that Always Free resources continue after standard trial expiry and card charges do not occur unless the account is upgraded; certain special trial offers can be suspended. OCI Budgets are soft limits and alerts are evaluated every 24 hours. A budget alert is not a hard spending cap. If account state is paid/Pay-As-You-Go or unknown, the current zero-spend gate is NO-GO.

## 2. Home Region

Profile menu → Tenancy Details. Capture only the Home Region label. Redact tenancy name/OCID and personal information.

## 3. A1 Compute limits

Navigation → Governance & Administration → Tenancy Management → Limits, Quotas and Usage. Select Compute and Home Region where available. Capture A1 OCPU and memory Service Limit / Usage / Available. A missing row means UNKNOWN, not zero.

## 4. HSM key-version limits

On Limits, Quotas and Usage select Key Management. Capture HSM-protected key-version Service Limit / Usage / Available. Do not create a Vault, Secret or key. Oracle's published Always Free allowance is not proof of this tenancy's actual availability; read the actual quota.

## 5. Existing VCN and IPv6 state

Only inspect existing resources. Do not create a VCN, add IPv6, add a prefix, or modify routes.

1. Networking → Virtual Cloud Networks.
2. If a VCN exists, inspect CIDR Blocks/Prefixes or IP Administration.
3. Record whether it has Oracle-assigned GUA /56, BYOIPv6, ULA, or no IPv6 prefix.
4. Inspect existing subnet details. Record Public/Private and whether IPv6 /64 is assigned.
5. Inspect existing Gateways: Internet Gateway, NAT Gateway, Service Gateway.
6. Inspect existing route table summaries. Record whether `::/0` points to the Internet Gateway.
7. Inspect effective security-list and NSG rules: IPv6 SSH TCP/22 from `::/0`? unrestricted/all IPv6 egress? Any exact egress CIDR allowlist?
8. Record whether the VCN uses OCI's Internet Resolver or a custom DNS resolver. Do not change it.

## 6. Existing billing and cost visibility

Inspect only existing billing/usage pages. Record subscription type, visible usage/credit state and any account-level usage summary. Do not share payment instrument details. Do not create a budget or assume an existing budget is a spending cap. Oracle calls budgets soft limits and evaluates alerts periodically every 24 hours.

## 7. Neon Data API IPv6 boundary

The canonical Neon main branch has Data API disabled. Do not enable it on main and do not create a branch as part of this checklist.

Only after a separate disposable Neon child branch and Data API activation are explicitly authorized:
- retrieve the branch-specific Data API URL;
- record the public hostname only; never share tokens;
- resolve A and AAAA records, TTL and resolver provenance;
- verify IPv6-only TLS/HTTPS with hostname/SNI and certificate validation;
- determine whether the AAAA destination set is stable and can be allowlisted without broad egress.

This checklist does not authorize that test.

## 8. Redaction and sharing

Redact tenancy name/OCID, email, billing contact, payment details, resource names/OCIDs, public/private IPs, CIDRs and IPv6 addresses, keys, certificates, secrets, tokens, and account-specific support identifiers. Share only high-level states and quota limit/usage/available values.

No signup, account creation, payment-method addition, upgrade, budget creation, resource creation, quota increase, route/security-rule change, or Neon change is permitted at this gate.
