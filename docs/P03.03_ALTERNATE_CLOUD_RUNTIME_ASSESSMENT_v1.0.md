## 1. Executive decision

The OCI evidence gate remains open because no redacted read-only OCI subscription, Home Region, quota, network or billing evidence has been supplied. The prior OCI hypothesis (Always-Free-only A1 + public GUA IPv6/IGW + exact Neon Data API HTTPS) remains conditional and unprovisioned.

A fresh review identified **Trigger.dev Cloud Free** as the strongest newly reviewed managed-task candidate for a small synthetic pilot. Its advertised Free plan is $0/month, requires no credit card, includes $5/month of usage credits, 20 concurrent runs, unlimited task definitions, 10 schedules, Dev and Prod environments, and only one day of logs/query history. Its managed workers execute task code without the project provisioning a VM; the vendor describes tasks as having no fixed execution timeout. It charges by compute-seconds plus run invocations. These characteristics fit bounded asynchronous task execution better than request-only functions or CI schedulers.

**This is not a production approval.** Five blocking limitations remain:

1. Free plan has no contractual 99% uptime commitment; the vendor terms apply the 99% availability undertaking only to paying customers. Free support is at the vendor's discretion.
2. The $5 monthly credit pool is small and is a ceiling on included compute, not a free model/API allowance. External LLM/API, network, data, and upstream service costs are separate and are not included in the estimate below. When Free credits are exhausted, the vendor says an upgrade is required to keep tasks running.
3. Trigger.dev disclosed a security incident on 1 November 2026. Its 6 November report says 0.66% of customer environments were affected; an attacker obtained root API keys for some environments and accessed environment variables. Trigger.dev says affected keys were revoked, impacted customers were notified, and it found no evidence of broader customer data or production database access. The incident's technical attack vector had not been publicly disclosed in the report reviewed here.
4. Free tier provides only 20 concurrent runs, 10 schedules and one day of retained logs/query history. This is not a high-availability or full observability foundation.
5. A zero-local and non-GitHub-operational deployment route for this exact project has not been verified. Trigger.dev's documented deployment model bundles code from the project and deploys it to managed workers. Do not silently substitute GitHub as an operational dependency or a local computer as a permanent host.

**Decision:** keep Trigger.dev disabled as a candidate. It may be considered only for a separately authorized, synthetic-only, non-sensitive bounded QA pilot after the owner confirms that an already-existing Free account is available, reviews and accepts the current terms, confirms the account is not paid, and the non-local/non-GitHub deployment and kill-switch paths are documented. Do not place Neon credentials, database passwords, third-party API tokens, personal data, wallet keys, private signing keys or payment credentials in Trigger.dev during the initial evaluation.

## 3. Transparent compute-only estimate

Published formula for the small 1x machine:

`estimated run cost = (execution seconds × USD 0.0000338) + USD 0.000025 invocation fee`

The following figures are arithmetic estimates using the published rates and the $5 monthly included credits. They are not an approved budget, do not include tax or any third-party provider charges, and assume every run uses only the small 1x machine.

| Active execution per run | Estimated cost per run | Approximate runs from $5 |
|---:|---:|---:|
| 5 seconds | $0.000194 | 25,773 |
| 10 seconds | $0.000363 | 13,774 |
| 30 seconds | $0.001039 | 4,812 |
| 60 seconds | $0.002053 | 2,435 |

The vendor's own example states that 100 daily 10-second runs on small 1x would cost approximately $1.09 over 30 days. This is compute plus run fees only. An agent that calls a paid model, browser, search, data feed, database, storage service or another external API can incur a separate bill outside this Trigger.dev estimate. No assumption is made that model inference or external integrations are free.

When the included Free credits are used, the pricing FAQ says an upgrade is required to continue running tasks. The project must therefore fail closed on credit exhaustion. Never choose an upgrade, add billing, enable paid usage, or route to a paid provider automatically.

## 4. Security and secret-custody assessment

### 4.1 Incident evidence

Trigger.dev's report dated 6 November 2026 says the 1 November incident affected 0.66% of customer environments and included unauthorized access to environment variables. The attacker obtained customer root API keys for some environments; those keys could access environment settings, including variables. In some impacted environments, the attacker listed run, deployment and schedule metadata. Trigger.dev says it found no evidence of access to other customer data, its production databases, customer services or dashboard accounts. It reports that it blocked the attacker, revoked potentially impacted API keys, notified impacted customers, engaged incident-response experts and law enforcement, and introduced IP whitelisting for scoped API keys and OIDC support. The detailed attack vector was not disclosed in the report reviewed.

This is a material recent security event, not proof that the current platform remains compromised. Equally, the vendor's remediation statement is not independent certification of the current environment. If an existing account is later reviewed, inspect its impact notification and current security controls. A clean account must not be inferred merely from the passage of time.

### 4.2 Initial pilot data classification

Allowed in any separately approved initial synthetic pilot:
- synthetic task IDs and idempotency keys;
- synthetic JSON fixtures;
- non-sensitive build/version identifiers;
- public test outcomes and aggregate timing/cost measurements.

Prohibited in initial pilot:
- Neon database connection strings/passwords, runtime credentials or Data API signing secrets;
- any API token for models, search, browser, exchange, wallet, payment or third-party service;
- private keys, seed phrases, signing material, wallet/session credentials or payment information;
- personal/KYC data, customer data, confidential commercial records or unreleased opportunity payloads;
- any live transfer, trade, payout, signing, external submission or account mutation.

Trigger.dev states environment variables are encrypted at rest and decrypted just-in-time for run execution. This does not make the platform equivalent to an HSM, nor does it remove the risk from project root API-key compromise. No private signing key may be stored there. For any later non-sensitive credential pilot, require scoped API keys, IP restrictions or OIDC where applicable, no root key in code/logs, revocation/rotation procedure, access review, and an independently verified account status.

## 5. Deployment and portability gate

Trigger.dev's published model deploys code bundled from the project's `trigger` folder to its managed worker infrastructure. A local CLI workflow is documented, and a Git-based deployment path exists. Neither proves an operationally acceptable path for this project under its current constraints.

Before any deployment is considered, establish a repeatable route that:
- requires no user's laptop, desktop, WSL, persistent local computer or self-hosted runner;
- does not make GitHub Actions or GitHub-hosted infrastructure an operational dependency;
- requires no paid IDE, build runner, model API or hosting tier;
- can pin source commit, build environment, artifact digest and deployment identity;
- can verify the exact deployed task version and roll it back or disable it;
- keeps secrets out of source, prompts, SQL, build logs and artifacts;
- can stop all schedules and task dispatch without deleting evidence;
- can report credit usage and enforce a pre-defined safety margin before reaching the Free limit.

**Current result:** `DEPLOYMENT_ROUTE_WITHOUT_LOCAL_OR_GITHUB_OPERATIONAL_DEPENDENCY = UNKNOWN`. No deployment or account was attempted.

## 7. Proposed future pilot contract (not authorized by this document)

A later, separately approved Trigger.dev evaluation could be limited to:

1. One synthetic-only task and at most one schedule.
2. At most one concurrent run for initial tests, with a strict short runtime and a small invocation ceiling.
3. No Neon access, no external network calls, no model calls, no third-party APIs and no credentials.
4. Synthetic event → deterministic function → signed/hashed result artifact → independent read-back.
5. Capture source digest, build digest, task ID, run ID, start/end time, machine preset, active seconds and estimated credits.
6. Verify pause/stop behavior, duplicate event idempotency, retry ceiling and failure handling.
7. Confirm Free credit status and alert settings before every run. On unknown usage, incident alert, unexpected data egress or approaching credit ceiling, stop and preserve logs.
8. After the test, remove or disable the task/schedule only under a separately approved cleanup step and verify that no live schedules or secrets remain.

This contract is a design proposal only. It does not authorize account creation, terms acceptance, deployment, API calls, task dispatch, credential injection, or cleanup actions.
