## 1. Architecture retained from v1.3
An owner-created Google Apps Script time-driven trigger obtains the effective user's OIDC ID token using explicit openid scope and sends it over HTTPS to the existing isolated Neon Function route:
POST /internal/google/scheduler/dispatch

The Function verifies Google's RS256/JWKS signature, accepted issuer, exact scalar OAuth client audience, SHA-256 hash of the effective user's sub and fresh token time claims. It uses the existing Neon-managed database identity crypto_holdco_function. It does not use Neon Data API and does not create PostgreSQL roles, passwords, memberships or grants.

Neon Data API remains disabled on main and pilot. The Data API role-claim path is rejected because PostgreSQL role selection requires a valid role claim and corresponding authenticator membership. Do not circumvent this with role mutation.

## 2. v1.4 source hardening
### 2.1 Fail-closed Apps Script installation gates
The Apps Script source now checks five explicit Script Properties before a time-driven trigger can be installed:
- P03_03_INDEPENDENT_WBS_ACCEPTED
- P03_03_GOOGLE_IDENTITY_PREFLIGHT_VERIFIED
- P03_03_FRESH_TOKEN_PER_TICK_VERIFIED
- P03_05_QUOTA_RECOVERY_COMPLETE
- GOOGLE_SCHEDULER_TRIGGER_APPROVED

All five must equal the literal string "true". Missing or false values cause installSchedulerTrigger() to return INSTALL_GATES_NOT_SATISFIED before it obtains the install lock or calls ScriptApp.newTrigger().
The repository does not set these properties. No Apps Script project exists, no property values are configured, and no trigger has been created. These are procedural owner-controlled guardrails, not a cryptographic substitute for independent reviewer approval.

### 2.2 Exact Google OIDC audience
The runtime verifier now requires claims.aud to equal the configured OAuth client audience as a scalar string. It rejects array-valued multi-audience tokens even if the pinned client ID appears in the array. This matches the Apps Script owner preflight, which requires payload.aud to be a string. A dedicated signed-token negative test confirms a multi-audience token is denied before JWKS fetch.
