## Credential schema and validation
The isolated pilot token tables now contain:
- `token_hash` (one-way SHA-256 hash only)
- `subject`
- `enabled`
- `created_at`
- `scopes text[]`
- `expires_at timestamptz`
- `revoked_at timestamptz`
- `rotation_group uuid`
- `last_used_at timestamptz`

The migration is `db/migrations/pilot/20261127_scoped_token_lifecycle.sql`.

Existing API operator token scope set:
- `agents:read`
- `demo:run`
- `tasks:write`
- `tasks:read:any`
- `metrics:read`
- `a2a:write`

Existing cron credential scope: `dispatch:run` only.

Both existing credentials have a 30-day expiry at **27-Dec-2026 09:44:32 UTC**. Their underlying raw values and hashes were not read or exposed. No new token was created, and no token was rotated.

Validator functions:
- `runtime.validate_api_token(text,text)`
- `runtime.validate_cron_token(text,text)`
- PL/pgSQL, VOLATILE, SECURITY DEFINER.
- Owner: `crypto_holdco_owner`.
- Fixed search path: `pg_catalog,runtime`.
- Enforce enabled=true, `revoked_at IS NULL`, future `expires_at`, and exact required scope.
- Update `last_used_at` only when a matching token validates successfully.
- PUBLIC execution revoked; Function role has EXECUTE, but no direct token-table SELECT.

The Function source patcher replaces direct table lookups with these validator calls. It also fails the deterministic build if old blanket token-table lookups, unbounded `request.json()` or raw internal error responses remain.

## Explicitly open assurance items
These are not marked complete:
1. A positive authenticated bearer-token canary and valid authenticated HTTP request have not been independently tested. Raw credentials were not extracted. A write attempt to create a synthetic credential canary was blocked by the execution safety guard, and no workaround was attempted.
2. A secure token issuance/rotation/reissue procedure with a protected delivery channel is not implemented. Plan and complete it before the existing credentials expire on 27-Dec-2026.
3. The current owner operator token has privileged `tasks:read:any`; task records are not yet bound to token subject. This is restricted to the single-operator pilot and must be solved before multi-tenant/buyer access.
4. `last_used_at` update is in deployed code, but no successful bearer-authenticated request has yet been observed after the migration, so the positive update is not yet evidenced.
5. No per-day invocation budget is live. P03.05 must add persistent app-level budgets and the 80% soft-stop against actual custom project caps. Those ceilings remain design-only until deployed and tested.
6. Seven specialist entries are logical roles inside one deterministic Function. Independent LLM agents and live provider model calls are not implemented.
