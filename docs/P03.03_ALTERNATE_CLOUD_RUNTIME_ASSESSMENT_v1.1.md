## 1. Executive decision

The OCI account-evidence gate remains open. No redacted read-only account/subscription, Home Region, A1/HSM quota, VCN/IPv6, effective egress or billing evidence has been supplied. OCI Always Free A1 plus public GUA IPv6/IGW and an exact Neon Data API HTTPS destination remains the first conditional persistent-VM hypothesis, not an approved or provisioned runtime.

A further official-source review tested four candidates that looked attractive by headline free-tier features:

- **Northflank Sandbox:** always-on compute, two services, two jobs, one database/addon and up to $20/month of included Northflank Cloud resources. However, Northflank's billing documentation explicitly says every user must add a payment method before creating resources, regardless of selected plan, and says the free Developer Sandbox should not be used for production applications. REJECT for this mission under no-payment-method, no-paid-fallback and production requirements.
- **Modal Starter:** $0 monthly plan price plus compute, $30/month included compute credits, five deployed cron jobs, 100 containers and limited scheduled/web functions. But Starter usage is pay-as-you-go, the pricing page distinguishes Team/Enterprise environment-level budgets from Starter, Modal says a payment method is required so apps are not interrupted when credits expire, external Model API tokens are billed from the first request, and the documented deploy route is CLI-based with GitHub Actions shown as a common CI/CD route. REJECT for now under the no-payment-method/no-silent-spend/no-local-or-GitHub-operational-dependency constraints.
- **Fly.io Free:** $5/month allowance is not a hard no-bill boundary: the pricing page says that after $5 usage the account moves to Pay As You Go and continues running, and the Free tier requires a credit card. REJECT.
- **Hugging Face Spaces:** Static Spaces are free, but the official overview states that compute-backed Gradio/Docker Spaces require a paid plan; free hardware Spaces sleep after inactivity and stop executing. REJECT as an autonomous worker runtime; a static frontend is a different product role and does not satisfy P03.03.

These findings reinforce rather than relax the project's safety rule: a headline free allowance is not proof of a hard spend stop, no-card eligibility, production permission, a durable worker, or a valid deployment path. No newly reviewed candidate displaces OCI as the primary conditional persistent-runtime hypothesis. Trigger.dev Cloud Free remains only a conditional synthetic-pilot candidate from v1.0; it is not promoted to production.

**Decision:** P03.03 remains PARTIAL; Quota Governor remains `PAUSE_DEGRADED` / `work_allowed=false`; production recurring work remains PAUSED. No candidate is approved for production 24x7 execution.

## 2. Candidate findings

### 2.1 Northflank Developer Sandbox

Published Sandbox envelope:
- Up to two services, two jobs and one addon/database; pricing page also states up to one BYOC cluster.
- Northflank's pricing page lists always-on compute/no sleeping and up to $20/month of free Northflank Cloud resources.
- Free tier is described as suitable for exploration, hobby projects and tests.

Hard blockers:
- Northflank's official billing documentation states that **all users must add a payment method before creating resources, regardless of plan**.
- The same documentation says the free tier **should not be used for production applications**.
- BYOC does not make infrastructure free: the chosen cloud provider bills its infrastructure directly.

Decision: `REJECT_NO_PAYMENT_METHOD_AND_NONPRODUCTION_SANDBOX`. Always-on/no-sleep is not enough to overcome these blockers. Do not create an account, attach a card, create resources or treat the Sandbox as production-ready.

### 2.2 Modal Starter

Published Starter envelope:
- $0 monthly subscription price plus usage; $30/month included compute credits.
- Up to 100 containers, 10 GPU concurrency, three workspace seats, limited Scheduled and Web Functions, real-time metrics/logs, and one-day log retention.
- Five deployed cron jobs and 1 TiB/month included network egress are listed for Starter.
- Modal supports managed serverless Functions, Sandboxes and queues; Starter is suitable for bounded asynchronous compute, not a continuously resident worker process.

Positive control and unresolved blockers:
- Modal's official Budgets documentation states that a Workspace budget is a **hard outer cap** for total workspace spend during a monthly billing cycle. A Workspace budget is distinct from an Environment budget; the latter is Team/Enterprise-only. The maximum Workspace budget depends on prior successful charges and can increase if incremental usage charges succeed.
- The precise behavior for a fresh Starter workspace with $30 included credits and a desired hard zero-out-of-pocket cap has not been proven. The documentation does not establish here whether included credits are counted against the Workspace budget in the manner required by this mission, nor the exact minimum permitted budget for a new workspace. Do not assume.
- Modal's own FAQ says usage on Starter is pay-as-you-go. Included compute credits apply to eligible Function/Sandbox CPU, memory and GPU; Model API token charges are separate and begin from first request. A workspace hard cap may provide useful spend protection, but it must be tested/documented for the exact account before any resource is created.
- Modal's Startup-credit FAQ explains that a payment method is required so apps do not become interrupted when credits run out. Whether every ordinary Starter onboarding route permits use without a payment method is not conclusively established by the pages reviewed; account state remains UNKNOWN and no card may be added under current policy.
- Modal's official `modal deploy` reference uses a CLI command. Deployment examples show source paths, local profiles and GitHub Actions CI/CD. No acceptable no-laptop/no-GitHub-operational-dependency route was demonstrated for this project.
- No-fee use under Modal Terms is provided as-is without support, warranties or representations.

Decision: `CONDITIONAL_RESEARCH_CANDIDATE_NOT_APPROVED`. Do not add a payment method, provision compute, issue a Modal token, deploy, invoke, or route any model call through the platform. Revisit only if a no-card Starter path, zero-out-of-pocket Workspace budget and compliant deployment path are independently proven.

### 2.3 Fly.io Free

Published pricing page shows a $5 monthly usage allowance, up to three Machines and three Sprites, plus a Developer Managed Postgres database funded from the same allowance. It expressly says that once usage reaches $5, the account moves to Pay As You Go and keeps running; the Free plan also requires a credit card.

Decision: `REJECT_AUTOMATIC_PAYG_CONTINUATION_AND_CARD_REQUIRED`. A free allowance that transitions to paid usage without a project-approved hard stop violates the locked policy.

### 2.4 Hugging Face Spaces

Official Spaces documentation distinguishes Static Spaces from compute-backed Spaces. It states that the default CPU Basic hardware has no hourly cost, but a Space running compute (Gradio or Docker) requires a paid plan; Static Spaces are free. It also says Spaces on free hardware go to sleep after a period of inactivity and stop executing until used again. Default ephemeral disk is not persistent.

Decision: `REJECT_AS_WORKER_RUNTIME`. Static hosting may be a separate presentation layer only if later justified, but it cannot run a continuously active agent workforce under these documented rules.

## 4. Operational architecture implications

1. Keep Neon as canonical mission/evidence/task/quota/revenue ledger only. Its runtime credential and quota gates remain unresolved.
2. Do not replace an unverified persistent runtime with a chain of nominally free providers. Automatic provider hopping is prohibited until account-specific eligibility, billing boundary, terms, security, data location, runtime behavior and deployment have been independently verified.
3. Keep the agentic workforce and scheduled dispatch paused. Do not simulate activity to prevent provider idle reclamation.
4. Any later candidate-specific trial must be separately authorized and narrowly bounded. Synthetic-only means no Neon credentials, external API/model tokens, customer/personal/KYC data, wallet or signing keys, payment details, live opportunity submissions, external claims, transfers or transactions.
5. Any provider with a card/payment method requirement is ineligible under the current no-payment-method gate. Any provider that transitions to pay-as-you-go or invoices after allowance exhaustion is a NO-GO unless a verifiable hard spend stop is proven and separately approved.
6. No-fee credits cannot be treated as free inference: third-party model APIs, search, browser, data feeds, storage, and transfer may be billed separately.
